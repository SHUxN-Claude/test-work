# 目標値検索ツール【行丸ごと版】 見出し行自動検出の修正 (2026-07-16)

## 症状
会社PCで検測CSVを「元データ」シートに貼り付けても、目標値(60件)が
「目標値検索結果まとめ」に1件も反映されない。

## 原因
会社のシステムが出力するCSVは

- 1行目: 「25734件のデータが検索されました」という帯行
- 2行目: 空行
- 3行目: 見出し(No, 事業本部コード, …, 高低（左）目標値F, …)
- 4行目以降: データ

という形式なのに対し、ツールは「元データの1行目 = 見出し」固定で
作られていたため、目標値F系の列を1つも認識できず、検索結果が0件になっていた。

## 修正内容 (fix_header_autodetect.py)
xlsx内のXMLを直接書き換える。

1. `作業用!G10:G19` を新設 — 元データ1〜10行目それぞれに
   「目標」と「F/Ｆ」を含むセルがあるかを COUNTIFS で判定 (0/1)
2. `作業用!A2` を新設 — 見出し行番号 = G10:G19で最初に1が立つ行 (無ければ1)
3. `作業用!B2:EU2` (見出しミラー150セル) —
   `IF(元データ!X$1="","",元データ!X$1)` → `IF(INDEX(元データ!X:X,$A$2)="","",…)`
4. `目標値検索結果まとめ!B4:EU4` (見出し表示150セル) — 同様に `作業用!$A$2` 参照へ
5. `目標値検索結果まとめ!A1/A2` — 空データ判定・150列超過判定を
   1行目固定から先頭10行に拡張
6. `xl/workbook.xml` — `fullCalcOnLoad="1"` を付与(開いた時に全再計算)、
   calcChain.xml は数式変更に伴い削除(Excelが自動再構築)
7. 「はじめに」シートの使い方①に帯行OKの注記を追記

データ行の走査(作業用!A30以降のSUMPRODUCT)は元データ2行目以降を絶対行番号で
見る設計のため変更不要。帯行・見出し行はフラグ「1」を含まないので誤検出しない。

## 検証
- LibreOffice headless で全再計算 →
  見出し行=3 を自動検出、「検索結果： 該当 48 行（目標値の項目 60 件）」
- Pythonで元データを独立に走査した結果(該当48行・フラグ計60個、
  目標値F系列10本 = 列23,28,33,38,44,49,54,59,80,84)と完全一致
- 該当行(5609, 5610, 6208, 6209, …)・黄色ハイライト用の値列マッピングも一致
- 見出しが1行目にある従来形式のCSVでも従来どおり動作(検出が1行目になるだけ)

※LibreOfficeでは COUNTA(EU1:XFD10) が空でも1を返すクセがあり
150列超過の注意書きが誤表示されるが、修正前の数式でも同じ挙動で、
Excelでは正しく0になるため実害なし。

## 追加修正 (2026-07-16 修正版2): 条件付き書式の色が Excel で表示されない

### 症状
- 結果シート4行目の見出しが虫食い状態(目標値F系の列しか見えない)
- 目標値フラグの「1」だけがセル上で見えない(0は見える)
- オレンジ/赤/黄の色付けが一切出ない

### 原因
条件付き書式用の書式定義(styles.xml の dxf)の塗りつぶしが
`<patternFill patternType="solid"><fgColor …/></patternFill>` と
書かれていた。dxf の solid 塗りは `bgColor` で指定する必要があり、
Excel では塗りが描画されず「白文字だけ適用」される状態になっていた。
- 濃紺塗り+白文字(見出し行) → 塗りが出ず白文字が不可視 = 見出し虫食い
- 赤塗り+白文字(フラグ「1」) → 同様に「1」が不可視
- オレンジ塗り(黒文字)の目標値F見出しだけは黒文字のまま見えていた

LibreOffice は fgColor のみでも塗りを描画するため、検証時に見逃した。

### 修正
dxfs 内の塗り4件を Excel 標準の
`<patternFill><bgColor rgb="…"/></patternFill>` 形式に変更 (fix_styles)。
通常セル書式(cellXfs 用 fills)は対象外。
